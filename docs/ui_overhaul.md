# UI 전면 개편 (나무판자 → Franuka RPG UI Pack)

> 2026-08-16 시작. 기존 medieval.png 목재 텍스처를 쓰는 화면 11개를
> Franuka 팩으로 전면 교체. 타이틀 화면은 나중에 별도로 크게 갈아엎을
> 예정이라 이번 범위에서 제외.

## 원칙
화면마다 **성격에 맞는 서로 다른 프레임/톤**을 쓴다 (예전에 나무판자로
전부 통일했다가 단조로워졌던 실수 반복 금지). 단, 장식 없는 "중립
유틸리티 버튼" 3종(`Button_04A`/`Button_01B`/`Button_02B`)은 여러
화면에 재사용 — 이건 의도적 디자인 시스템.

## 이미 완료됨 (기준선, 겹치면 안 됨)
- **스펠북**: `Spellbook.png`, `Button_01A`, `Button_02A`, `BGbox_01A`(팝업)

## 진행 방식
2~3개씩 묶어서 순서대로 진행 (한 번에 다 하면 검증 어려움). 각 배치
끝날 때마다 이 표의 상태를 ✅로 갱신.

## 참고
목업은 파이썬 근사 스케일링이라 실제 Godot `StyleBoxTexture` margin은
화면 적용 시 재측정 필요 (퀘스트로그 때 `BGbox_07A` patch 28처럼).

## 실측한 9-slice margin (2026-08-18, 1·2번 작업분)

늘렸을 때 가장자리 장식이 반복/뭉개지지 않는 최소값을 텍스처마다 픽셀 단위로
재서 정했다. 재는 방법: "중앙 열들이 서로 완전히 같아야 가로로 늘려도 안전하고,
중앙 행들이 서로 같아야 세로로 안전하다"는 기준으로 최소 margin을 찾고,
실제 목표 크기로 렌더해서 눈으로 확인.

**버튼 좌우가 비대칭인 이유**: `Button_04A`/`05A`는 가운데(원본 x 46~49)에
긁힌 자국 픽셀이 박혀 있다. 대칭 margin을 쓰면 그 자국이 늘어나 버튼 전체를
가로지르는 띠가 되거나(STRETCH), 일정 간격으로 반복돼 물방울무늬처럼 보인다(TILE).
깨끗한 열은 18~45번뿐이라 왼쪽 18 / 오른쪽 50으로 잡아 그 구간만 늘어나게 했다.
세로 14는 같은 이유(깨끗한 행이 14~17번뿐)다.

**배너 높이**: 두 배너 다 글자가 리본 아래 접힌 부분에 걸리길래, 늘어나는
중앙 행이 리본 본체 안(단색)이라는 걸 확인하고 배너를 원본보다 키웠다
(Small 32→48, Medium 64→72). `content_margin`은 늘린 뒤의 본체 범위에 맞춰
계산해서 글자가 정확히 리본 가운데 오도록 했다.

## 3번(HUD) 작업 메모 (2026-08-18)

**바는 원본 높이(32px)를 반드시 지켜야 한다.** `Slider01_Box`는 세로로 늘릴 수 있는
균일한 중앙 행이 아예 없다 — 위아래가 통째로 테두리 장식이라 조금만 늘려도 프레임이
뭉개진다. 그래서 체력/마나/경험치바를 전부 높이 32로 두고, 실제로 보이는 홈(y 8~27,
20px)에 숫자 라벨을 얹는 방식으로 맞췄다. 바 사이 간격은 위쪽 투명 여백 8px이
겹치도록 26px씩 띄워 시각적으로는 6px 간격이 된다.

**`Button_02D`는 원본이 16x16짜리 작은 버튼을 2배로 그린 것**이라 프레임이 26px
고정으로 들어간다. 처음에 기존 크기(42x42) 그대로 뒀더니 안쪽 면이 16px밖에 안 남아
아이콘이 테두리를 타고 넘었다 → 버튼을 52x52로 키워 24px을 확보했다. 좌우가
비대칭(12/14)인 것도, 세로가 Normal과 Pressed에서 다른 것(16/12 vs 18/10)도
얼룩이 아니라 원본 그림 자체가 그렇게 그려져 있어서다 (Pressed는 눌린 느낌을 내려고
음영이 2px 아래로 내려가 있다).

**스탯카드 배경은 Franuka 프레임을 안 썼다.** 남은 배경박스(`BGbox_04A`/`04C`)는
둘 다 천 주머니 그림이라 상시 노출되는 작은 카드에 안 맞고, 나머지는 4~10번에 이미
배정돼 있다. 상시 HUD는 뒤로 물러나 있어야 하므로 어두운 반투명 패널(StyleBoxFlat)로
두고, 색깔은 바 프레임의 어두운 자주색 계열에 맞췄다.

**`hud.gd`도 함께 손봤다** (동작이 아니라 표시 값만):
- 경험치바는 코드로 만들어지므로(`_build_xp_bar`) 스타일박스를 같은 텍스처로 교체.
  체력/마나바와 규칙이 갈라지지 않게 9-slice 여백도 같은 상수를 쓴다.
- `OBJECTIVE_LABEL_PADDING` 36 → 56, `OBJECTIVE_PANEL_MIN_WIDTH` 180 → 210.
  명판 좌우 끝에 20px짜리 금속 브래킷이 생겨서, 글자가 거기 물리지 않게 안쪽 여백을
  키워야 패널 폭 자동 조절이 계속 맞는다.

## 4·5번 작업 메모 (2026-08-18)

**`Button_03C`는 9-slice가 아예 불가능하다.** 원형 보석 버튼이라 평평한 구간이 한 픽셀도
없다 — 억지로 중앙 2px을 늘리면 원이 사각형으로 뭉개진다. 대신 **margin을 전부 0으로 두고
버튼 크기를 원본의 정수배(64x32 → 128x64)로 맞췄다**. margin 0이면 9-slice가 그냥 전체
확대로 동작하고, 정확히 2배 + nearest 필터라 픽셀이 깨지지 않는다.

**`Button_03C`에는 "OK"가 그림에 그려져 있다.** 그래서 `text`를 빈 문자열로 두고 텍스처의
OK를 그대로 label로 쓴다 (`text = "확인"`을 남기면 OK 위에 겹쳐 찍힌다). 게임이 전부
한국어인데 이 버튼만 영문이므로, 거슬리면 `Button_03B`(글자 없는 원형)로 바꾸고 텍스트를
얹는 방법이 있지만 원 안쪽이 좁아 "확인"이 넘친다.

**`BGbox_04B`는 margin 42가 필요하다.** 천 주머니라 가운데(원본 x 36~39)에도 주름이
그려져 있어서, 40 미만으로 잡으면 그 주름이 늘어나 세로줄처럼 보인다.

**`ending_record_menu.gd`에 구분선 생성만 추가했다.** 엔딩 슬롯은 원래 코드로 만들어지므로
(`_build_slots`) 항목 사이 `Divider_02`도 같은 자리에서 만든다. 잠금/해금 글자색 상수도
새 패널(먼지 낀 장미색) 위에서 읽히도록 조정했다.

## 6·7번 작업 메모 (2026-08-18)

**게임오버는 프레임 없는 쪽을 골랐다.** 세 안(프레임 없음 / `BGbox_01B` 원본색 /
`BGbox_01B` 어둡게)을 실제로 렌더해 비교한 결과:
- 원본색은 밝은 라벤더라 죽음 화면과 정면으로 어긋난다.
- 어둡게 깔면 `BGbox_01B`의 강철·청회색 디테일이 사라져서, 프레임이 기여하는 게
  "내용을 상자에 가둔다"는 것뿐이다. 그러면 패배가 그냥 흔한 대화상자 하나가 된다.
- 프레임을 빼면 나머지 화면이 전부 프레임을 가진 이 개편 안에서 게임오버만 **종류가
  다른 순간**으로 읽힌다. Dim을 0.92 → 0.95로 더 올려 배경을 거의 삼켰다.

**`Button_06A`는 `Button_04A`/`05A`와 같은 계열**이라 얼룩 위치(원본 x 8~17, 46~49,
82~95)가 완전히 같다. 그래서 좌우 비대칭 18/50을 그대로 쓴다.

**Pressed 상태는 세로 여백이 다르다.** `Button_06A`/`01B` 둘 다 눌린 느낌을 내려고
음영이 2px 내려가 있어서, Normal 기준 값을 그대로 쓰면 캡이 세로로 늘어난다
(`Button_02D`와 같은 현상). 상태별로 T/B를 2px씩 옮겼다.

**컷신 본문 두루마리는 그대로 뒀다.** `medieval.png`의 양피지 스크롤인데 목재 프레임이
아니고, 이걸 바꾸면 컷신 화면 전체 인상이 달라진다. 7번 범위는 확인 팝업이다.
다만 스킵 버튼은 목재였어서 `Button_04A`로 같이 넘겼다 — 팝업만 바꾸면 한 화면에
두 팩이 섞인다.

## 8·9·10번 작업 메모 (2026-08-21) — 표 전체 완료

**인벤토리는 `Slot_02_Empty` 한 종류만 썼다.** 표에 "장비별 실루엣 9종"이라고 적혀 있었지만,
그 실루엣들은 무기/방패/투구 같은 **칸이 정해진 장비창(페이퍼돌)**용이다. 이 게임 인벤토리는
`GameState.inventory.keys()`를 앞에서부터 채우는 평범한 가방이라 칸에 종류가 없고, 아이콘이
실루엣 위에 그대로 덮이므로 넣어도 보이지 않는다. 그래서 빈 칸 프레임만 12칸에 균등 배치했다.
배경 그림이 medieval의 "INVENTORY" 격자였던 탓에 슬롯 좌표가 그 그림에 맞춘 실측값이었는데,
이제 격자를 코드가 계산하므로 `SLOT_POSITIONS` 상수를 없애고 `_slot_position()`으로 바꿨다.

**대화창은 NPC 패널도 같은 `BGbox_02A`를 쓴다.** 처음엔 "NPC 패널 기존 유지"를 그대로 지켜
어두운 커스텀 패널을 새로 만들었는데, 기존 글자색이 진한 갈색(`COLOR_NORMAL`)이라 어두운
배경 위에서 읽히지 않았다. 원래도 두 패널이 같은 나무 텍스처를 공유했으므로 같은 프레임으로
되돌리는 쪽이 맞다. "기존 커스텀 유지"에 해당하는 건 얼굴 카드와 호감도 바이고, 그 둘은 그대로다.

**`Button_01D`(±·페이지 버튼)는 평평한 구간이 6x2뿐이다.** `Button_02D`처럼 작은 정사각
버튼을 2배로 그린 것이라 안쪽이 거의 다 장식이다. 32x32 원본 그대로 쓰면 `<` 글자가 들어갈
자리가 없어서, 실측 여백(L12 T14 R14 B16)으로 48x44까지 키웠다.

**이미 커밋된 화면에서 버그를 하나 발견해 고쳤다.** 저장/불러오기의 `Button_02B` Pressed가
Normal과 같은 세로 여백(12/12)을 쓰고 있었는데, 측정해보니 눌린 그림은 2px 아래로 내려가
있어 T14/B10이 맞다. 48px 높이 버튼에서 눌림 상태가 세로로 늘어나던 문제다.

**범위 밖이라 두고 온 것**: 상점을 열면 좌상단 HUD가 그대로 보인다. `ShopMenu`/`WeaponShopMenu`가
`hud.gd`의 `BLOCKING_GROUPS`에 없어서인데, 이번 개편 전부터 그랬고 비주얼 교체와 무관하다.
