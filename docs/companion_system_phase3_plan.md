# 동료 시스템 Phase 3 — 전투 통합 계획

Phase 1(`docs/companion_system_backend_plan.md`, 백엔드 골격)과 Phase 2(필드 동행)는 구현/커밋 완료.
이 문서는 **Phase 3(전투 통합)의 단계 분할과 미결정 사항(Q5~Q8) 권고안**까지만 다룬다. 구현은 결정 후 별도로.

확정 스펙 출처: `docs/companion_system_options.md` §6.

## 1. 조사 요약 — Phase 3에 직결되는 현재 구조

### 1-1. 규칙과 연출이 "버퍼 리플레이"로 이어져 있다 (가장 중요)

적 턴은 **매니저가 전부 즉시 해결한 뒤, 씬이 그 기록을 나중에 애니메이션으로 재생**하는 구조다:

- `BattleTurnManager._resolve_enemy_turn()`이 피해까지 전부 적용하고 시그널만 쏜다.
- `battle_scene.gd:1118` `_on_enemy_attack_resolved()`는 **연출을 하지 않고 `_enemy_attacks` 배열에 dict를 쌓기만 한다.**
  `_on_monster_recovered()`(`:1130`)도 같은 배열에 쌓여 순서가 보존된다.
- 그 뒤 씬이 배열을 순서대로 훑으며 돌진/피격/회복 연출을 재생한다.

**Phase 3에 주는 의미**: 동료 공격/피격을 추가할 때 새 연출 파이프라인을 만들 필요가 없다.
**시그널에 인자를 하나 늘리고, 버퍼 dict에 키를 하나 늘리는 것**이 확장의 전부다.
규칙(3-a/3-b/3-c)과 연출(3-d)을 서로 다른 커밋으로 분리할 수 있는 근거도 이것이다.

### 1-2. `_player_sprite` 64곳은 두 부류로 깨끗하게 갈린다

이게 Phase 3-d의 유일한 진짜 위험 지점이라 미리 경계선을 그어둔다.

| 부류 | 의미 | 대표 위치 | Phase 3에서 |
|---|---|---|---|
| **수행자** | 플레이어가 *카드를 쓰는* 주체 | `:1504~1550`(돌진/대시), `:1746`(캐스트 차지), `:3131~3599`(트리플헬릭스/스위프트/메테오), `:2974~2979`(마나흡수/흡혈), `:1571~1646`(방어/회피/반격/버프 팝업) | **손대지 않는다** — 동료는 카드를 쓰지 않는다 |
| **피격자** | *맞거나 회복되는* 아군 개체 | `:1901`(몬스터 돌진 목표), `:1931~1962`(반격/회피/방어/피격 연출), `:2403`(상태 배지) | `_ally_sprite_at(index)`로 교체 |
| **셋업/배치** | 스프라이트·그림자·HUD 생성/배치 | `:2628~2632`, `:2812~2818` | 아군 배열 방식으로 확장 |
| **조건부** | 힐 카드의 회복 팝업 | `:1563~1566`, `:1603~1606` | **3-e에서만** 대상 스프라이트로 |

대략 **50곳이 "수행자"라 불변, 10~14곳만 교체 대상**이다. 64곳 전부를 건드리는 작업이 아니다.

### 1-3. 적 다개체 machinery가 아군에 그대로 이식된다 (씬 트리가 대칭)

`battle_scene.tscn`의 구조가 이미 좌우 대칭이다:

| 아군 | 적군 | 부모 |
|---|---|---|
| `View/PlayerShadow` | `View/MonsterShadow` | `View` |
| `View/Actors/PlayerSprite` | `View/Actors/MonsterSprite` | `View/Actors` |
| `View/HUD/PlayerCard` | `View/HUD/MonsterCard` | `View/HUD` |

적 쪽 `_setup_sprites()`(`:2627`)는 **0번은 씬의 원본 노드를 쓰고, 1번부터는 `_clone_sibling()`(`:2688`)으로
런타임 복제**한다. `_layout_monsters()`(`:2832`)가 배치를, 병렬 배열들(`_monster_sprites`/`_monster_shadows`/
`_monster_card_panels`/`_monster_hp_bars`/`_status_badges` …)이 개체별 참조를 든다.

→ 아군도 똑같이 `_ally_sprites[0] = _player_sprite`(원본)로 두고 동료만 복제하면 된다.
**중요: `_clone_sibling()`이 런타임 복제라 `battle_scene.tscn` 파일은 한 줄도 안 건드려도 된다.**

주의 하나: `PlayerCard`에는 `ManaBar`/`GoldLabel`이 있는데 동료는 마나도 골드도 없다(Phase 1 설계).
복제한 동료 카드는 그 둘을 숨겨야 한다.

### 1-4. 전투 UI는 100% 마우스다 (키보드 단축키가 0개)

- 손패는 버튼 클릭(`_hand_buttons`, `_on_card_pressed`), 타겟은 몬스터 클릭(`_input` → `_monster_at_point`).
- `_input()`(`:1256`)은 **타겟팅 모드에서만** 동작하고, 키보드는 `ui_cancel`(취소) 하나뿐.
- InputMap 전체에도 전투용 액션이 없다(`move_*`/`interact`/`run`/`toggle_compass`가 전부).

→ Q7(동료 액티브 발동 키)의 답이 여기서 갈린다(§5).

### 1-5. 하드코딩 지점은 4곳 (Phase 1에서 식별한 그대로, 줄 번호만 이동)

| 위치 | 현재 | 바꿀 것 |
|---|---|---|
| `battle_turn_manager.gd:626` | `if GameState.get_flag("player_hp") <= 0: break` | "살아있는 파티원이 없으면 중단" |
| `:651` | `_resolve_single_attack(attacker)` — 대상 인자 없음 | 대상 인자 추가 |
| `:673` 부근 | `GameState.damage_player(damage_taken)` | `target.take_damage()` |
| `:571` 부근 | `end_turn()`의 `player_hp <= 0` → `_finish_battle(true)` | 파티 전원 다운 판정 |

### 1-6. `CompanionData`에 시각 정보가 전혀 없다 (Phase 3-d의 선행 과제)

현재 필드는 `name/max_hp/damage_min/damage_max/passive/active`뿐이다. 전투 연출에 필요한
`battle_sprite_path` / `frame_size` / `scale` / `portrait_sheet_path` / `portrait_region` /
`foot_from_center` / `body_width`가 **하나도 없다**.

게다가 수치가 그냥 비어 있는 게 아니라 **플레이어와 규격이 다르다**:

| | 플레이어(전투) | 유서프(필드 에셋) |
|---|---|---|
| 시트 | `Body_A/Idle_Base/Idle_Up-Sheet.png` (뒷모습) | `Npc's/Wizzard/Idle/Idle-Sheet.png` |
| 프레임 | **64px**, `PLAYER_SCALE = 3.4` | **32px** |
| 보유 애니메이션 | Idle 계열 방향별 | Idle / Run / Death (**방향 구분 없음**) |

→ 같은 화면 크기로 맞추려면 동료 스케일은 6.8쯤 되어야 하고, **전투 화면은 아군을 뒤에서 보는데
유서프 시트에는 뒷모습이 없다.** 이건 코드 문제가 아니라 에셋 결정이라 §8에 질문으로 뺐다.

## 2. 단계 분할 — 3-a ~ 3-e

### 설계 원칙: 모든 중간 커밋에서 화면이 깨지지 않을 것

순진하게 "규칙 먼저, 연출 나중"으로 가면 **동료가 화면에 없는데 데미지만 들어가는 구간**이 생긴다
(피격 팝업이 플레이어 자리에 뜬다). 반대로 연출을 먼저 하면 동료가 서 있기만 하고 아무것도 안 한다 —
이쪽이 훨씬 덜 이상하다.

그래서 **3-a에서 타겟 가중치의 초기값을 "동료 0"으로 두고**(= 기존과 100% 동일 동작),
연출이 완성된 3-c 시점에 상수만 실제 값으로 바꾸는 방식을 권고한다. 인프라는 미리 들어가되
동작은 마지막에 켜지는 구조라, 매 커밋이 안전하고 되돌리기도 상수 한 줄이다.

### 권고 순서

| 단계 | 내용 | 켜지는 것 | 위험 |
|---|---|---|---|
| **3-a** | 피격 대상 일반화 (규칙 계층) | 없음(가중치 0) | 낮음 |
| **3-b** | 패배 판정 = 파티 전원 다운 | 없음(동료 무피격이라 실질 동일) | 중 |
| **3-d** | 아군 다개체 연출 | 동료가 화면에 등장(행동 없음) | **높음** |
| **3-c** | 동료 자동 공격 + 가중치 실제값 전환 | **여기서 동료가 실제로 참전** | 중 |
| **3-e** | 힐/셀프버프 카드 아군 타겟 UI | 아군 타겟 카드 | 중~높음 |

`3-d`가 `3-c`보다 앞이라 번호와 순서가 어긋나지만, 문서 전체에서 **문자는 작업 종류, 표의 위에서
아래가 실행 순서**로 읽으면 된다(이름을 바꾸면 Phase 1/2 문서의 참조가 깨진다).

### 3-a. 피격 대상 일반화 (규칙 계층만)

- `_resolve_single_attack(attacker)` → `_resolve_single_attack(attacker, target)`
- `_pick_attack_target()` 신설 — 살아있는 파티원 중 가중치 추첨(§3). **초기 가중치는 동료 0**
- `enemy_attack_resolved` 시그널에 `target_index: int` 추가
- **방어/피하기/반격은 플레이어를 겨냥한 공격에만 적용** (§3의 부속 결정)
- `battle_scene`은 새 인자를 버퍼 dict에 담기만 하고 아직 안 쓴다

독립 커밋 가능: **O** (동료가 없으면 기존과 완전히 동일, 있어도 가중치 0이라 동일)

### 3-b. 패배 판정 = 파티 전원 다운 (+ Q6 승리 회복 확장, 2026-09-07 범위 확정)

- `end_turn()`/`_resolve_enemy_turn()`의 `player_hp <= 0` 검사를 `_is_party_wiped()`로 교체
- 플레이어가 다운된 동안 카드 조작 잠금(`battle_scene._is_interactive()`에 조건 추가)
- 플레이어 다운이면 `is_hand_exhausted()`와 같은 자리에서 자동 턴 종료 (§8 Q13 결정: 연출 속도는 기존 그대로,
  배속/스킵 UI 없음)
- **`_finish_victory()` 확장 (Q6 결정)**: 보상(골드/XP/드롭)은 다운 여부와 무관하게 전액 그대로 지급.
  승리 시 25% 회복을 동료에게도 동일 비율로 적용. 플레이어가 HP 0으로 승리했을 경우 회복 후 최소 1 이상을
  명시적으로 보장(하한 보장)

독립 커밋 가능: **O** (동료 0명이면 파티 = 플레이어 1명이라 판정 결과가 기존과 같다)

### 3-d. 아군 다개체 연출 (가장 큰 단계)

- `_ally_sprites` / `_ally_shadows` / `_ally_card_panels` / `_ally_hp_bars` / `_ally_status_badges` 배열 도입.
  **0번은 기존 `_player_sprite`/`_player_shadow`/`PlayerCard` 원본을 그대로 담는다** (적 0번과 같은 방식)
- 동료만 `_clone_sibling()`으로 복제 → `.tscn` 무수정
- `_layout_allies()` 신설 — 플레이어 왼쪽/뒤쪽으로 쌓는다(적 배치의 좌우 반전)
- `_ally_sprite_at(index)` 헬퍼 (`_monster_sprite_at`과 같은 폴백 규약)
- **§1-2의 "피격자" 부류만** 교체. 수행자 부류는 손대지 않는다
- 복제된 동료 카드의 `ManaBar`/`GoldLabel` 숨김
- `CompanionData`에 시각 필드 추가(§1-6)

독립 커밋 가능: **O** (동료가 서 있기만 함)
서브 분할 권장: **3-d-1**(스프라이트/그림자/배치/HUD 카드) → **3-d-2**(피격 연출 대상 전환 + 상태 배지)

### 3-c. 동료 자동 공격 + 패시브 훅

- `_resolve_companion_turn()` 신설. **턴 순서: 플레이어 턴 종료 → 동료 전원 공격 → 적 턴**
  (동료 공격으로 적이 죽으면 적 턴 전에 판정되어 불필요한 반격을 안 맞는다)
- 새 시그널 `companion_attack_resolved(companion_index, target_index, damage)` — 기존 버퍼에 함께 쌓아
  재생 순서 보존
- `CompanionState.tick_round()` / `consume_passive_trigger()`를 `_tick_status_rounds()` 옆에서 호출
- 패시브는 **훅만 연결**하고 실제 효과(유서프 회복)는 Phase 4
- 3-a의 타겟 가중치를 실제 값으로 전환 ← **동료가 실제로 참전하는 지점**

독립 커밋 가능: **O**

### 3-e. 힐/셀프버프 카드의 아군 타겟 UI

- `_targets_an_enemy(card) -> bool`을 3분류로 확장 (`ENEMY` / `SELF` / `ALLY`)
- `_needs_target()`이 아군 대상 카드에도 걸리게, `_begin_targeting()`이 아군 마커도 생성
- `_ally_at_point()` 추가 (`_monster_at_point`의 아군판)
- 매니저: HEAL 효과가 대상에 따라 `PlayerCombatant.heal()` / `CompanionState.heal()` 분기
- §1-2 "조건부" 부류(힐 팝업)를 이때 대상 스프라이트로 전환

**반드시 3-d 이후**여야 한다 — 클릭할 아군 스프라이트가 존재해야 타겟팅이 성립한다.

독립 커밋 가능: **O**

## 3. Q5 권고 — 적 AI의 타겟 선택

### 권고: **가중치 랜덤, 플레이어에 더 큰 가중치** (플레이어 2 : 동료 각 1)

`_pick_attack_target()`이 **몬스터마다 새로 추첨**한다(3마리가 전부 플레이어만 때리면 다운이 너무 빠르다).
죽은 파티원은 후보에서 제외.

| 안 | 2인 파티 기준 플레이어 피격률 | 문제 |
|---|---|---|
| 플레이어 우선 | 100% | 동료 HP 영속성과 "파티 전원 다운" 패배 조건이 **사실상 사문화**된다. 목숨이 2개인 셈 |
| 완전 랜덤 | 50% | 기존 1:1 밸런스에서 **너무 급격히 이탈** — 카드/포션 경제가 1인 피격 기준으로 튜닝돼 있다 |
| **가중치 2:1** | **67%** | 이탈이 완만하면서 동료도 실제로 맞는다 |

근거:
1. 기존 밸런스(100% 피격)로부터의 이탈이 완만하다.
2. 동료가 실제로 맞아야 동료 HP 영속성(§6 Q1 확정)과 모닥불 회복(Q3 확정)이 의미를 갖는다.
3. Phase 5에서 4인이 되어도 **플레이어 가중치 상수 하나**를 파티 크기에 맞춰 키우면 피격률을 유지할 수 있다.

### 부속 결정: 방어/피하기/반격은 플레이어 전용

`_pending_defense` / `_pending_dodge` / `_pending_counter`는 **플레이어를 겨냥한 공격에만 적용**할 것을 권고.

- 카드 설명과 일치한다(플레이어가 자신을 지키는 카드).
- 동료가 맞는 걸 방어 카드로 막을 수 있으면 "동료 HP 관리"라는 새 압박이 즉시 무력화된다.
- 구현도 단순하다 — `_resolve_single_attack()`에서 `target`이 플레이어일 때만 소모 분기를 탄다.

주의: 이러면 **동료를 때리는 공격은 방어 풀을 소모하지 않고 지나간다.** 기존 주석(`:612~619`)의
"뻥튀기 방지" 규칙과 충돌하지 않는지 구현 시 재확인할 것 — 오히려 플레이어 대상 공격만 세므로 규칙이 더 단순해진다.

## 4. Q6 — 플레이어 다운 상태로 승리했을 때 — **결정 (2026-09-07, 사용자 확정)**

**권고안 그대로 채택, 3-b에 포함해서 같이 구현한다.** 이유: 3-b가 들어가는 순간 "플레이어 다운 상태로
승리"가 처음으로 가능해지는데, 이 처리 없이 3-b만 나가면 승리 회복이 동료에게 적용 안 되고 플레이어도
0%로 다음 전투에 들어갈 수 있어 "모닥불까지 동료 혼자 이겨야 하는" 사실상 진행 불가 버그가 바로
재현된다. 그래서 3-b와 분리하지 않고 한 커밋에 묶는다.

### 채택안: **보상 전액 지급 + 승리 회복도 그대로 적용 (동료에게도 확장)**

현재 `_finish_victory()`(`:2510`)는 골드/XP/드롭을 주고 `heal_player_partial(0.25)`로 HP를 회복시킨다.

1. **보상 차등 없음.** 다운 자체가 이미 충분한 페널티다(그 전투의 남은 턴 동안 플레이어의 모든 조작권 상실).
   여기에 보상까지 깎으면 이중 페널티다.
2. **승리 회복은 반드시 준다.** 안 주면 HP 0으로 다음 전투에 진입 → 즉시 다운으로 시작 →
   모닥불까지 동료 혼자 이겨야 하는 **사실상 진행 불가 상태**가 된다.
3. **회복 하한 보장.** HP 0에서 승리했다면 최소 1 이상이 되도록 명시적으로 보장할 것
   (현 수치로는 자연히 1 이상이지만, `player_max_hp`가 작아지는 상황에 대비).
4. **동료에게도 같은 비율(25%) 승리 회복을 준다.** ← 이게 핵심 추가 권고.
   동료 회복 수단이 모닥불뿐이면 전투마다 깎이기만 해서, 모닥불 간격이 먼 구간에서 영구 전멸에 수렴한다
   (Phase 1 §6 Q3에서 지적한 구멍이 모닥불 결정만으로는 완전히 막히지 않는다).

XP도 그대로 준다(근거 1과 동일).

## 5. Q7 권고 — 동료 액티브 발동 수단

### 권고: **아군 HUD 카드 위의 액티브 버튼(1차) + 숫자키 단축키(선택적 보조)**

확정 스펙의 문구는 "특정 키로 발동"이지만, §1-4에서 확인했듯 **전투 UI에는 키보드 단축키가 하나도 없다.**
키보드 전용 기능을 하나만 넣으면 조작 문법이 갈라진다.

1. **기존 문법과 일치** — 손패도 버튼 클릭이다.
2. **쿨다운을 버튼 위에 그대로 표시**할 수 있다(손패 버튼이 `disabled`로 사용 불가를 보여주는 방식 재사용).
   키보드 전용이면 쿨다운 상태를 알릴 자리를 따로 만들어야 한다.
3. **Phase 5에서 4인이 되어도 키 고갈이 없다** — 카드마다 버튼이 하나씩 늘 뿐이다.
4. "특정 키로 발동"은 숫자키(1/2/3)를 **추가로** 붙여 충족시킨다. 버튼이 정답 UI, 키는 가속기.

구현 범위 주의: 새 InputMap 액션은 `project.godot` 수정이 필요하다.
**Phase 3에서는 버튼만 만들고 키 단축키는 Phase 4로 미루는 것**도 합리적이다 —
액티브 스킬의 실제 효과 자체가 Phase 4 범위다.

## 6. Q8 권고 — 동료의 "쉬는 턴"

### 권고: **쉬는 턴 없음. 매 턴 확정 공격.**

몬스터의 마나 리듬(`monster_state.gd:29~36`)은 "적이 쉬는 턴 = 플레이어에게 반격 기회"라는
**플레이어의 판단 거리**를 만들기 위한 장치였다.

동료에게 같은 걸 붙이면 그 의미가 사라진다:
- 플레이어가 동료를 조작하지 않으므로(확정 스펙), 동료가 쉬는 턴은 기회가 아니라 **그냥 DPS 감소**다.
- 플레이어가 통제할 수 없는 변수라 "운이 나빴다"는 감상만 남고 분산만 커진다.
- Phase 1에서 이미 `mana` 필드를 의도적으로 뺐고, **액티브 쿨다운이 리듬을 담당**한다고 결론냈다.

밸런스 손잡이는 `CompanionData`의 `damage_min/max` 하나로 충분하다 — 너무 강하면 수치를 낮추면 된다.
나중에 리듬이 정말 필요해지면 `CompanionState`에 필드를 추가하는 재작업은 작다.

## 8. 새로 확인이 필요한 것

**Q12. 동료 전투 스프라이트를 무엇으로 할 것인가?** — **결정 (2026-09-06, 사용자 확정)**
후보 (a)/(b)/(c) 대신 **네 번째 방향**으로 확정: 플레이어 쪽을 바꾼다. 플레이어의 전투 스프라이트를
뒷모습(`Idle_Up` 계열)에서 **옆모습(`Idle_Side` 계열)으로 교체**하고, 동료(유서프/엘라라/로한)도 전부
옆모습으로 통일한다. 근거 확인 완료: `Body_A/Animations/`에 `Idle_Base`뿐 아니라 `Hit_Base`/`Death_Base`/
`Slice_Base`/`Pierce_Base` 등 대부분의 애니메이션 카테고리에 이미 `_Side` 버전이 같은 팩 안에 존재함
(새 아트 불필요, 시트 참조만 교체). **Phase 3-d 작업에 추가 항목으로 포함**: 전투에서 실제로 쓰이는
플레이어 애니메이션 카테고리를 전부 조사해서 `_Up` → `_Side` 참조로 교체하고(존재하지 않는 카테고리가
있으면 그때 보고), 동료 스프라이트도 처음부터 옆모습 기준으로 배치. 기존 "정면 Idle 그대로" 권고는 폐기.

**Q7. 동료 액티브 발동 수단** — **결정 (2026-09-06, 사용자 확정)**: 버튼 UI까지 통째로 **Phase 4로 이동**.
Phase 3-c는 자동 공격 + 패시브 훅까지만(권고안 그대로), 액티브 버튼은 실제 효과(마력장벽)와 함께
Phase 4에서 한 번에 만든다 — 눌러도 아무 일 없는 죽은 버튼을 Phase 3에 남기지 않기 위함.

**Q13. 플레이어 다운 이후 전투는 어떤 속도로 진행되는가?** (3-b) — **결정 (2026-09-07, 사용자 확정)**
**(a) 기존 연출 속도 그대로** 채택. 배속/스킵 UI는 3-b 범위에 넣지 않는다.

**Q14. 동료도 상태이상(버프/디버프)의 대상이 되는가?**
`CompanionState.status`는 Phase 1에서 이미 `StatusEffects`를 들고 있다. 3-d의 상태 배지를 아군 전원으로
확장할지, 플레이어만 유지할지. → **일단 플레이어만 표시** 권고(동료에게 상태를 거는 카드가 아직 없다).
3-e에서 아군 버프 카드가 실제로 생기면 그때 배지를 확장.

**Q15. `enemy_attack_resolved`의 `target_index` 인덱스 공간은?**
Phase 1 §8 Q4에서 "아군 전용 시그널 신설(b)"로 결정했지만, 적 공격의 *대상*은 아군이라 기존 적 시그널에
아군 인덱스가 실려야 한다. → **파티 배열 인덱스(0=플레이어)를 그대로 싣고, 몬스터 인덱스와는
파라미터 이름으로 구분**(`attacker_index` vs `target_index`) 권고. 음수 오버로드는 쓰지 않는다.
